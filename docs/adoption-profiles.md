# Adoption profiles

Profiles help adopters use the smallest adequate method.

## Profile A — Solo human plus AI

Use `WORKING`, `CANON`, `ARCHIVE`, receipts, one exact-byte separate review, frozen candidates, retractions, and `INDEX.json`. Run the checker locally and in CI.

## Profile B — Small research or engineering team

Add named reviewer classes, environment receipts, aggregate units, handoffs, tool-scope logs, and explicit correction or receipt supersession for contradictions.

## Profile C — Regulated or high-consequence work

BVM alone is insufficient. Add domain-specific quality systems, access controls, signatures, retention rules, validated execution environments, formal approvals, and external audit. Do not relabel BVM structural conformance as regulatory compliance.

## Profile D — Low-consequence scratch work

Do not force every note through the full method. Keep scratch state outside canon. Introduce receipts when a claim will guide decisions, survive a session boundary, be shared, or be costly to correct.
